## 🟡 P1 — 省市命名后缀不统一（建议修，影响城市筛选/统计/聚合）

### 1. 城市名 "市" 后缀两种写法并存 —— 18 个城市、114 条受影响
例如：`南京`(11) vs `南京市`(1)、`杭州`(14) vs `杭州市`(4)、`深圳`(4) vs `深圳市`(1)、
`长沙`(8) vs `长沙市`(2)、`西安`(7) vs `西安市`(1) 等。
→ 地图/城市下拉会把「杭州」和「杭州市」当成两个城市，统计也被拆散。

### 2. 省份名 "省" 后缀两种写法并存 —— 16 个省份
例如：`浙江`(19) vs `浙江省`(9)、`江苏`(15) vs `江苏省`(9)、`广东`(29) vs `广东省`(1) 等。

### 3. 直辖市 province 写成 "X市"（双后缀）—— 约 24 条
`province='上海市'/'北京市'/'天津市'/'重庆市'`，与 `city` 重复且不规范（如 id 3/28/38/79/92…）。

**建议统一规则**：所有 `city` 去掉末尾「市」；所有 `province` 去掉末尾「省」，直辖市/自治区归一
（`广西壮族自治区`→`广西`，`北京市`→`北京` 等）。

## 🛠 建议修复（已生成脚本，未执行）

修复 SQL 见 `scripts/ingest/fix_audit.sql`：

1. **P0**：逐条 `UPDATE` 把 9 条改回真实城市（上表）。
2. **P1**：
   ```sql
   UPDATE conventions SET city = CASE WHEN city LIKE '%市' THEN substr(city,1,length(city)-1) ELSE city END;
   UPDATE conventions SET province = CASE
     WHEN province='广西壮族自治区' THEN '广西'
     WHEN province LIKE '%市' THEN substr(province,1,length(province)-1)   -- 直辖市 X市→X
     WHEN province LIKE '%省' THEN substr(province,1,length(province)-1)
     ELSE province END;
   ```
3. **P2（可选）**：单日 `end_date IS NULL` 统一置为 `start_date`。

> 执行顺序：必须先做 P0（修正真实城市），再做 P1（去后缀），否则 P1 会把已错填的「北京」原样保留。
> 修改后建议重新跑一次 `regeo_verify` 确认坐标仍与城市匹配。
